# Урок 00a. Наш стенд: закрытый контур, Open WebUI, Chatbox и Kilo Code

> Уровень: Старт · Время: ~30 минут

**После урока вы сможете:**
- объяснить, из чего состоит учебный стенд и почему данные не покидают контур;
- войти в Open WebUI или подключить Chatbox, выбрать модель и получить первый ответ;
- подключить Kilo Code в VS Code к корпоративному серверу моделей и сразу выставить безопасные права.

Все примеры курса работают на **закрытом контуре** компании. Модели запущены на наших серверах, у них нет выхода в интернет, а ваши тексты не уходят во внешние облачные сервисы. В открытом интернете есть облачные чат-боты, устроенные по тем же принципам. В курсе мы с ними не работаем: всё, что вы узнаете, применяется к локальным моделям.

## Из чего состоит стенд

```text
                 ЗАКРЫТЫЙ КОНТУР КОМПАНИИ (нет выхода в интернет)
 ┌──────────────────────────────────────────────────────────────────┐
 │  Вы                                                              │
 │   ├─ браузер ──► Open WebUI  (чат, пресеты, базы знаний)         │
 │   ├─ Chatbox  (приложение на компьютере: чат и Work Mode)        │
 │   └─ VS Code + Kilo Code  (агенты code / ask / plan / debug)     │
 │                    │                    │                        │
 │                    ▼                    ▼                        │
 │      vLLM — сервер моделей (OpenAI-совместимый API)              │
 │        qwen-chat    — универсальная модель для чата и разбора    │
 │        qwen-coder   — агентная работа в Kilo Code                │
 │        deepseek-r1  — «думающая» модель для сложного анализа     │
 │        bge-m3       — модель для поиска по базам знаний          │
 │                    │                                             │
 │      MCP-сервер Jira  ──►  Jira Data Center (учебный проект HELP)│
 └──────────────────────────────────────────────────────────────────┘
```

Пять частей:

1. **vLLM** — программа на сервере с видеокартами. Она загружает локальные модели с открытыми весами (семейства Qwen, DeepSeek и другие) и отвечает на запросы по тому же протоколу, что и известные облачные сервисы (его называют **OpenAI-совместимым API**). Благодаря этому к ней подключаются и Open WebUI, и Chatbox, и Kilo Code.
2. **Open WebUI** — чат в браузере, похожий на привычные чат-боты. Подходит для всех ролей: задать вопрос, разобрать документ, сделать свой пресет-помощник, подключить базу знаний. Пресетами и базами знаний можно делиться с коллегами.
3. **Chatbox** — приложение для компьютера (Windows, macOS, Linux). Работает напрямую с сервером моделей, а история чатов и настройки хранятся **на вашем компьютере**, а не на общем сервере. Есть два режима: **Chat Mode** — обычный чат, и **Work Mode** — агентный режим, где модель сама читает и пишет файлы в выбранной папке, вызывает инструменты и MCP, обращается к локальной базе знаний. Удобен тем, кому нужен агент без VS Code.
4. **Kilo Code** — расширение для редактора VS Code. Это агентная среда: модель в ней читает и меняет файлы в папке проекта, запускает команды и вызывает инструменты (подробно в [уроке 07](07-chto-takoe-agent.md)). Программировать для этого не нужно: папка с текстовыми файлами — тоже проект. Самые точные настройки прав, свои агенты и субагенты — здесь.
5. **MCP-сервер Jira** — «розетка», через которую агент может читать заявки из внутренней Jira ([урок 09](09-mcp.md)). Его разворачивает администратор, на старте курса он может быть ещё не подключён.

### Какой инструмент когда брать

| Задача | Open WebUI | Chatbox | Kilo Code |
|--------|-----------|---------|-----------|
| Быстрый вопрос, письмо, пересказ | да | да | можно, но избыточно |
| Помощник-пресет для всей команды | **лучше всего**: пресеты и базы знаний общие | нет, настройки только на вашем компьютере | нет |
| Личная база знаний из своих документов | да | да, хранится локально | через файлы проекта |
| Агент без VS Code: файлы в папке, MCP | ограниченно | **Work Mode** | — |
| Агент с тонкими правами, свои агенты и субагенты, дифф и откат | нет | частично | **лучше всего** |
| История только на своём компьютере | нет, на сервере | **да** | да, в папке проекта и настройках |

В курсе основная практика идёт в Open WebUI и Kilo Code, а для Chatbox в нужных местах даются варианты «то же самое в Chatbox».

## Паспорт стенда

Имена в курсе условные. Реальные адреса, имена моделей и способ получить ключ даёт администратор контура. Перепишите таблицу к себе в тетрадь проекта и заполните её:

| Что | Условное имя в курсе | У вас |
|-----|----------------------|-------|
| Адрес Open WebUI | `https://chat.corp.local` | |
| Адрес сервера моделей (Base URL) | `http://llm.corp.local:8000/v1` | |
| Модель для чата и разбора | `qwen-chat` | |
| Модель для агентов (с вызовом инструментов) | `qwen-coder` | |
| «Думающая» модель | `deepseek-r1` | |
| Размер контекстного окна моделей (`--max-model-len`) | например, 131 072 | |
| Как получить ключ доступа к серверу моделей | у администратора | |
| Откуда ставить Kilo Code (внутреннее зеркало или файл VSIX) | у администратора | |
| Откуда ставить Chatbox (внутреннее зеркало, разрешённая версия) | у администратора | |
| Модель для поиска по базе знаний в Chatbox (embedding) | `bge-m3` | |
| Учебный проект в Jira | `HELP` | |
| Адрес MCP-сервера Jira | `http://mcp-jira.corp.local:9000/mcp` | |

Имена моделей — это не названия версий, а «вывески», под которыми администратор опубликовал модели (параметр vLLM `--served-model-name`). Какая версия и какого размера стоит за вывеской, решает администратор. Подробнее о выборе — в [уроке 03a](03a-vybor-modeli.md), об устройстве сервера — в продвинутом материале [«Инфраструктура vLLM»](../ai-agents-sdlc/04-vllm-infrastructure.md).

## Шаг 1. Open WebUI: первый ответ

1. Откройте адрес Open WebUI из паспорта стенда и войдите учётной записью, которую выдал администратор.
2. Вверху чата выберите модель `qwen-chat`.
3. Напишите: «Объясни в трёх предложениях, что такое закрытый контур».
4. Посмотрите на интерфейс. Слева история чатов, вверху выбор модели. Справа открывается панель **Chat Controls**: в ней системный промпт и параметры текущего чата ([урок 04](04-prompting.md)). В меню **Workspace** — пресеты моделей и базы знаний (уроки 04 и 06).

Подключение Open WebUI к серверу моделей делает администратор (раздел Admin Settings → Connections). Вам ничего настраивать не нужно: если модель видна в списке, она подключена.

## Шаг 1b. Chatbox: подключение к серверу моделей

Этот шаг нужен, если вы будете пользоваться Chatbox. Его можно отложить.

**Установка.** Ставьте версию из внутреннего зеркала, которую разрешил администратор. Скачать установщик из интернета на рабочем компьютере в контуре нельзя, да и не нужно.

**Подключение** (по состоянию на октябрь 2026, названия пунктов могут немного меняться между версиями):

1. Откройте Chatbox → **Settings** (настройки в боковой панели) → **Model Provider**.
2. Внизу списка нажмите **Add** (добавить провайдера).
3. Заполните:
   - **Name** — «Корпоративный vLLM»;
   - **API mode** — **OpenAI API compatible**;
   - **API Host** — адрес сервера моделей из паспорта стенда. Путь (**API Path**) обычно оставляют по умолчанию — `/v1/chat/completions`. Если адрес в паспорте уже заканчивается на `/v1`, проверьте, чтобы `/v1` не получился дважды;
   - **API Key** — ваш ключ доступа.
4. Добавьте модели `qwen-chat`, `qwen-coder`, `deepseek-r1`. Для `qwen-coder` и `deepseek-r1` отметьте в возможностях модели вызов инструментов (tool use), для `deepseek-r1` — рассуждения (reasoning), если такие флажки есть. Без отметок модель считается «только текст».
5. Сохраните и нажмите **Check** — должно появиться сообщение об успешном подключении.

**Важно для контура.** В Chatbox есть встроенные облачные возможности: собственный облачный сервис моделей разработчика и поиск в интернете. В контуре ими пользоваться нельзя: выбирайте только провайдера «Корпоративный vLLM», не включайте веб-поиск и не ставьте MCP-серверы из встроенного списка — только те, что одобрил администратор ([урок 09](09-mcp.md)). Настройки телеметрии и обновлений согласуйте с администратором.

История чатов и ключ хранятся на вашем компьютере. Это плюс для приватности и минус для надёжности: если компьютер потерян или переустановлен, история пропадёт, а ключ окажется у того, у кого компьютер. Блокируйте экран и не храните в Chatbox то, что должно быть доступно команде, — для этого есть Open WebUI.

## Шаг 2. Kilo Code: подключение к серверу моделей

Если вы пока работаете только в Open WebUI, этот шаг можно отложить до [урока 07](07-chto-takoe-agent.md).

**Установка.** В контуре нет доступа к магазину расширений в интернете. Kilo Code ставится из внутреннего зеркала или файлом: VS Code → Extensions → меню «…» → **Install from VSIX**. Откуда взять файл и какую версию ставить, говорит администратор. Настройки телеметрии и автообновлений тоже согласуйте с ним.

**Подключение своего сервера моделей** (по состоянию на октябрь 2026, интерфейс может немного меняться между версиями):

1. Откройте Kilo Code в боковой панели и нажмите шестерёнку (**Settings**).
2. Вкладка **Providers** → внизу списка **Custom provider**.
3. Заполните поля:
   - **Provider ID** — `corp` (короткое имя латиницей);
   - **Display name** — «Корпоративный vLLM»;
   - **Provider API** — **OpenAI Compatible**;
   - **Base URL** — адрес сервера моделей из паспорта стенда;
   - **API key** — ваш ключ доступа;
   - **Models** — нажмите **Fetch models**, Kilo Code сам получит список моделей с сервера. Отметьте `qwen-coder` и `deepseek-r1`.
4. Нажмите **Submit**. Модели появятся в списке выбора в формате `corp/qwen-coder`.

**Обязательная донастройка в файле.** Для своих моделей Kilo Code не знает размер контекстного окна и не знает, умеет ли модель вызывать инструменты. Без этих значений он не сжимает длинную историю и не показывает заполнение контекста. Поэтому их нужно прописать в файле настроек. Глобальный файл лежит в `~/.config/kilo/kilo.jsonc` (на Windows `~` — это папка вашего пользователя). Можно попросить сам Kilo Code: «открой мой глобальный kilo.jsonc и добавь лимиты для моделей corp». Должно получиться примерно так (это пример, сверяйте с документацией вашей версии):

```jsonc
{
  "provider": {
    "corp": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Корпоративный vLLM",
      "options": {
        "baseURL": "http://llm.corp.local:8000/v1",
        // ключ берётся из переменной окружения, а не хранится в файле
        "apiKey": "{env:CORP_LLM_KEY}"
      },
      "models": {
        "qwen-coder":  { "name": "Qwen Coder (контур)",  "tool_call": true, "limit": { "context": 131072, "output": 16384 } },
        "deepseek-r1": { "name": "DeepSeek R1 (контур)", "tool_call": true, "reasoning": true, "limit": { "context": 65536, "output": 16384 } }
      }
    }
  },
  "model": "corp/qwen-coder"
}
```

- `limit.context` должен совпадать с размером окна на сервере (`--max-model-len` из паспорта стенда). Если поставить больше, сервер будет отвечать ошибкой на длинных задачах.
- `tool_call: true` — модель умеет вызывать инструменты. Это должно быть включено и на сервере (у vLLM — флаги `--enable-auto-tool-choice` и `--tool-call-parser`). Иначе агент будет «описывать» действия текстом вместо того, чтобы их выполнять.
- Ключ храните только в **глобальном** файле или в переменной окружения. Проектный `kilo.jsonc`, который лежит в папке проекта и может попасть в репозиторий, подстановку `{env:...}` намеренно не выполняет. Так вредный репозиторий не сможет украсть ваш ключ ([урок 10](10-bezopasnost.md)).

## Шаг 3. Сразу выставьте безопасные права

Важная деталь: в Kilo Code по умолчанию большинство действий агента **разрешены без вопросов**. Спрашивает он только при чтении файлов `.env`, при доступе к файлам вне папки проекта и при зацикливании. Для обучения это слишком смело.

Откройте **Settings → Auto Approve** и поставьте:

| Инструмент | Что делает | Ставим |
|------------|------------|--------|
| `read`, `glob`, `grep` | читать и искать файлы в папке проекта | Allow |
| `edit` | изменять файлы | **Ask** |
| `bash` | запускать команды в терминале | **Ask** |
| `webfetch`, `websearch` | ходить в интернет (в контуре его нет) | **Deny** |
| `external_directory` | файлы вне папки проекта | Ask |

Кнопку-щит в окне чата (автоподтверждение всех запросов) пока не включайте. Почему всё именно так, разберём в уроках [07](07-chto-takoe-agent.md) и [10](10-bezopasnost.md).

## Шаг 4. Проверка Kilo Code

1. Создайте пустую папку `pomoshchnik-zayavok` и откройте её в VS Code (File → Open Folder).
2. В Kilo Code выберите агента **ask** (он только читает и ничего не меняет) и модель `corp/qwen-coder`.
3. Напишите: «Какие файлы есть в этой папке?». Агент вызовет инструмент чтения папки и ответит, что она пустая.

Если ответ пришёл, стенд готов. Если нет, посмотрите таблицу ниже.

| Симптом | Что проверить |
|---------|---------------|
| Модели нет в списке | Правильный ли Base URL (с `/v1` на конце), нажали ли Fetch models |
| Ошибка 401 или 403 | Ключ доступа: опечатка, срок действия, нужен ли ключ вообще |
| Ошибка про длину контекста | `limit.context` больше, чем `--max-model-len` на сервере |
| Агент пишет «вызываю инструмент…» текстом, но ничего не происходит | На сервере не включены `--tool-call-parser` и `--enable-auto-tool-choice` или в настройках нет `tool_call: true` — к администратору |

> **Частая ошибка новичка.** Думать, что раз контур закрытый, то о безопасности можно не беспокоиться: оставить все права агента по умолчанию и вставлять в чат пароли. Закрытый контур защищает от утечки в интернет. Он не защищает от ошибок агента в ваших файлах, от утечки между отделами и от вредных инструкций, спрятанных в тексте заявок. Безопасные права выставляются в первый же день.

## Главное за 30 секунд

- Стенд — это vLLM с локальными моделями плюс клиенты: Open WebUI (чат в браузере, общие пресеты), Chatbox (приложение на компьютере, чат и Work Mode) и Kilo Code (агенты в VS Code). Данные не покидают контур.
- Реальные адреса, имена моделей и ключ даёт администратор. Запишите их в паспорт стенда.
- В Kilo Code свой сервер подключается через Custom provider → OpenAI Compatible. Для моделей обязательно задать `limit.context` и `tool_call`.
- В первый же день: `edit` и `bash` — Ask, интернет-инструменты — Deny, ключ — только в глобальном файле настроек.

## Короткий словарик урока

- **Закрытый контур** — внутренняя сеть компании без выхода в интернет. Модели, данные и инструменты находятся внутри неё.
- **vLLM** — программа, которая запускает локальные модели на сервере и отвечает на запросы к ним.
- **OpenAI-совместимый API** — распространённый «язык» запросов к моделям. На нём говорят и vLLM, и клиенты.
- **Open WebUI** — чат в браузере для работы с моделями контура.
- **Kilo Code** — расширение VS Code, агентная среда.
- **Chatbox** — приложение для компьютера с режимами Chat Mode (чат) и Work Mode (агент); история хранится локально.
- **Base URL** — адрес сервера моделей, к которому подключается клиент.
- **Ключ доступа (API key)** — личный пароль для программ. Хранится в секрете.
- **kilo.jsonc** — файл настроек Kilo Code: глобальный (для всех ваших проектов) или проектный.
- **Паспорт стенда** — ваша таблица с реальными адресами и именами моделей.

### Ответы к «Проверь себя»

1. Б. Модели запущены на серверах компании через vLLM, и запросы не покидают контур.
2. Open WebUI — чат в браузере с общими пресетами и базами знаний. Chatbox — приложение на компьютере с локальной историей, чатом и агентным режимом Work Mode. Kilo Code — агентная среда в VS Code с самыми точными правами, своими агентами и откатом изменений.
3. Без него Kilo Code не знает размер окна, не сжимает историю и не показывает заполнение контекста. Значение должно совпадать с `--max-model-len` на сервере.
4. Проектный файл может попасть в репозиторий и к коллегам. Кроме того, Kilo Code намеренно не подставляет `{env:...}` в проектном конфиге, чтобы вредный репозиторий не мог перенаправить ваш ключ на чужой адрес.
5. Да. Внутри компании тоже действуют правила доступа: историю чатов Open WebUI хранит сервер, у администраторов платформы может быть к ней доступ, а заявки читают люди из разных отделов.
6. Open WebUI: пресеты и базы знаний там общие, их можно открыть группе. Настройки и история Chatbox хранятся на одном компьютере.
