# Урок 09. MCP: единая розетка для инструментов

> Уровень: 3. Агенты · Время: ~25 минут

**После урока вы сможете:**
- объяснить, какую проблему решает MCP, и отличить MCP-сервер от MCP-клиента;
- подключить MCP-сервер Jira в Kilo Code и понять, как его подключают в Open WebUI;
- составить «паспорт» MCP-сервера и решить, какие права ему дать.

В [уроке 06](06-instrumenty-i-rag.md) мы узнали, что агенту дают инструменты. Но внутренних систем много (Jira, Confluence, Bitbucket, базы данных), и клиентов тоже несколько (Open WebUI, Kilo Code, собственные скрипты). Если каждый клиент отдельно «подружить» с каждой системой, получится хаос. MCP решает именно эту проблему.

## Проблема «каждый с каждым»

Вспомните время, когда у каждого телефона был свой разъём и для каждого нужен был свой кабель.

С инструментами для агентов было то же самое. Чтобы агент умел работать с Jira, кто-то писал специальную «переходку» между этим агентом и Jira. Другой клиент — новая переходка. Новая система — снова переходка.

```text
 Без единого стандарта:                 С MCP:
 Kilo Code  ── переходка ── Jira        Kilo Code  ─┐          ┌─ сервер Jira
 Kilo Code  ── переходка ── Confluence  Open WebUI ─┼── MCP ───┼─ сервер Confluence
 Open WebUI ── переходка ── Jira        скрипт     ─┘          └─ сервер базы
 Open WebUI ── переходка ── Confluence
 (каждая пара — своя переходка)         (каждый подключается один раз)
```

## Что такое MCP

**MCP** (Model Context Protocol, «протокол контекста модели») — открытый стандарт, по которому агентные среды подключаются к внешним инструментам и данным. Официальная аналогия — USB-C: один стандартный разъём вместо набора разных кабелей.

Как это устроено:
- **MCP-сервер** — «розетка» для конкретной системы. Он сообщает агенту: «у меня есть такие действия: найти задачу, прочитать задачу, добавить комментарий». Серверы делают и сами владельцы систем, и сообщество. Кроме инструментов, сервер может давать данные (их называют ресурсами) и готовые шаблоны промптов.
- **MCP-клиент** — среда, которая подключается к серверам и показывает их инструменты модели. У нас это Kilo Code, Chatbox и Open WebUI.

Итог: сервер для системы разворачивают один раз, и к нему может подключиться любой клиент с поддержкой MCP.

Есть два способа связи с сервером:
- **локальный (stdio)** — сервер запускается программой на вашем компьютере как «дочерний процесс»;
- **удалённый (Streamable HTTP)** — сервер работает на отдельной машине в контуре, клиенты обращаются к нему по адресу. 

## История и статус

- **25 ноября 2024** Anthropic (компания, создавшая модели Claude) анонсировала MCP и сразу открыла стандарт для всех.
- Стандарт поддерживает большинство популярных агентных сред, в том числе Kilo Code и Open WebUI.
- **9 декабря 2025** Anthropic передала MCP в Agentic AI Foundation (AAIF) под управлением Linux Foundation. Сооснователи фонда — Anthropic, Block и OpenAI. Теперь стандартом управляет независимый фонд, а не одна компания.


## MCP в закрытом контуре

В интернете есть каталоги готовых MCP-серверов и «маркетплейсы» внутри агентных сред. В контуре ими пользоваться напрямую нельзя: выхода в интернет нет, а главное, **MCP-сервер — это программа, которая получает доступ к вашим данным**. Поэтому порядок такой:

1. Нужный сервер выбирает и проверяет администратор вместе с безопасностью: кто автор, какая версия, какие известные уязвимости.
2. Проверенная версия переносится во внутреннее зеркало и разворачивается внутри контура.
3. Пользователи подключаются к уже развёрнутому серверу по внутреннему адресу.



## Подключение в Kilo Code

В Kilo Code (по состоянию на октябрь 2026): **Settings → MCP → Add Server → Remote**, затем имя `jira` и адрес сервера. В файле настроек это выглядит так (пример, сверяйте с документацией вашей версии):

```jsonc
{
  "mcp": {
    "jira": {
      "type": "remote",
      "url": "http://mcp-jira.corp.local:9000/mcp",
      // токен берётся из переменной окружения, а не хранится в файле
      "headers": { "Authorization": "Bearer {env:JIRA_PAT}" }
    }
  },
  "permission": {
    // все инструменты сервера jira — только с подтверждением
    "jira_*": "ask"
  }
}
```

Как это читать:
- `jira` — имя, под которым сервер виден в Kilo Code; его инструменты получают имена вида `jira_<инструмент>`;
- `type: remote` и `url` — удалённый сервер по внутреннему адресу;
- `headers` — заголовок с вашим токеном. Подстановка `{env:JIRA_PAT}` работает только в **глобальном** файле настроек (`~/.config/kilo/kilo.jsonc`). Проектный файл из репозитория её не выполняет: так вредный репозиторий не сможет отправить ваш токен на чужой адрес;
- `permission` — права на инструменты сервера, тем же механизмом, что и для встроенных инструментов. Можно точнее: чтение разрешить, а запись спрашивать.

Если MCP в задаче не нужен, его можно выключить (Settings → Agent Behaviour → MCP Servers). Описания инструментов занимают место в контексте, и без лишних серверов агент работает быстрее.

## Подключение в Chatbox

В Chatbox (по состоянию на октябрь 2026): **Settings → MCP → Add Server** и ручная настройка сервера: либо команда для локального сервера, либо адрес удалённого. Для нашего сервера Jira указываете адрес `http://mcp-jira.corp.local:9000/mcp` и заголовок с токеном, если сервер его требует. Инструменты сервера доступны модели в Work Mode ([урок 07](07-chto-takoe-agent.md)), его включают на панели Work Mode.

Два предупреждения для контура:
- в Chatbox есть встроенный список готовых MCP-серверов и установка «в один клик» по ссылке. Не пользуйтесь ими: это внешние серверы, не проверенные администратором. Только ручная настройка серверов из внутреннего списка;
- настройки и токен хранятся на вашем компьютере. Токен должен быть с узкими правами, как и для Kilo Code.

## Подключение в Open WebUI

В Open WebUI MCP-серверы **может добавлять только администратор**: Admin → Settings → Integrations → External Tool Servers → тип **MCP (Streamable HTTP)**. Это сделано намеренно: MCP-сервер работает с правами пользователя, и случайный сервер мог бы прочитать или вынести данные. Администратор открывает доступ к серверу нужным группам. Серверы, которые умеют работать только локально (stdio), подключают через прокси **mcpo**.

Пользователь включает инструмент в чате: меню «+» → Integrations / Tools → нужный сервер.

Документация Open WebUI прямо предупреждает: MCP подключает инструменты, но **не делает модель умнее** в их использовании. Слабая модель может игнорировать инструменты или путать аргументы. Для работы с инструментами берите модель, которая надёжно их вызывает (на стенде — `qwen-coder`, [урок 03a](03a-vybor-modeli.md)).

## Доверие к серверам

К MCP-серверу легко подключиться, и в этом же риск. **MCP-сервер — это код, которому вы даёте доступ к своим данным и действиям.** Относитесь к нему как к сотруднику, которому выдаёте пропуск:

- **Кто автор и какая версия.** Сервер из внутреннего зеркала, проверенный администратором, а не первый найденный.
- **От чьего имени работает токен.** Агент сможет всё, что может владелец токена. Для учебного проекта лучше отдельная учётная запись с правом только просматривать проект `HELP`.
- **Права задаются в самой системе.** Настройки «включить только такие-то инструменты» в самом сервере — удобство, а не граница безопасности (реальный случай с таким фильтром — в [уроке 10](10-bezopasnost.md)). Надёжная граница — права учётной записи в Jira.
- **Подтверждение действий.** Всё, что меняет данные или видно другим людям (комментарий, смена статуса), — только с вашим «да».
- **Данные тоже могут «приказывать».** Текст задачи, который вернул сервер, может содержать вредные инструкции. Это данные, а не команды ([урок 10](10-bezopasnost.md)).

> **Частая ошибка новичка.** Подключить MCP-сервер Jira со своим личным токеном, у которого есть права на все проекты и на запись, «чтобы точно всё работало». Тогда агент может сделать в Jira всё, что можете вы, включая ошибки от вашего имени. Начинайте с токена, у которого есть права только на чтение учебного проекта, и с `jira_*: ask`. Права расширяйте по одному, когда без них никак.

## Главное за 30 секунд
- MCP — открытый стандарт подключения клиентов (Kilo Code, Chatbox, Open WebUI) к инструментам и данным, «USB-C для ИИ». В Chatbox не пользуемся встроенным списком серверов — только серверы из внутреннего списка.
- В контуре серверы выбирает, проверяет и разворачивает администратор; пользователи подключаются по внутреннему адресу.
- Kilo Code: Settings → MCP → Add Server, токен только в глобальном конфиге через `{env:...}`, права `jira_*: ask`. Open WebUI: серверы добавляет только администратор.
- Надёжная граница — права учётной записи в самой Jira, а не фильтр в настройках сервера.

## Короткий словарик урока
- **MCP (Model Context Protocol)** — открытый стандарт подключения агентов к внешним инструментам и данным.
- **MCP-сервер** — программа-«розетка», которая даёт агенту инструменты, ресурсы и шаблоны промптов конкретной системы.
- **MCP-клиент** — среда, которая подключается к серверам: Kilo Code, Open WebUI.
- **Streamable HTTP / stdio** — удалённое подключение по адресу / запуск сервера на своём компьютере.
- **mcp-atlassian** — открытый MCP-сервер для Jira и Confluence, включая Data Center.
- **PAT (персональный токен доступа)** — личный ключ для программ в Jira Data Center; даёт те же права, что у владельца.
- **mcpo** — прокси, через который Open WebUI подключает локальные (stdio) MCP-серверы.

## Практика: шаг сквозного проекта

Время: 10–15 минут. Результат запишите в тетрадь проекта.

1. Узнайте у администратора и запишите **паспорт MCP-сервера Jira**:
   - какой сервер и какая версия развёрнута, кто её проверял;
   - адрес сервера;
   - какие инструменты он даёт (поиск задач, чтение задачи, комментарий и т. д.);
   - от чьей учётной записи будет токен и какие у неё права в Jira (какие проекты, чтение или запись);
   - подключён ли сервер в Open WebUI и для каких групп.
2. Отметьте, какие инструменты нужны помощнику: на старте — только «найти задачу» и «прочитать задачу». «Добавить комментарий» — позже и только с подтверждением.
3. Если сервер уже доступен, подключите его в Kilo Code по образцу выше. Поставьте `jira_*` в Ask, выберите агента **ask** и попросите: «Найди в проекте HELP открытые заявки и перечисли их номера и темы». Посмотрите, какие инструменты Jira вызвал агент.

*Если MCP-сервер ещё не развёрнут:* выполните пункты 1–2 по образцу и запишите, чего не хватает для запуска. На старте помощник будет работать с заявками из папки `zayavki/`. Это нормальный вариант: MCP добавляется, когда готов и проверен.

### Ответы к «Проверь себя»
1. Б. Сервер разворачивают один раз, и к нему подключается любой клиент с поддержкой MCP; безопасность MCP сам по себе не гарантирует.
2. Сервер даёт инструменты конкретной системы, клиент подключается к нему и передаёт инструменты модели. Клиенты на стенде — Kilo Code, Chatbox и Open WebUI.
3. MCP-сервер работает с правами пользователя и может читать и выносить данные. Поэтому подключение доверенных серверов — решение администратора, а пользователям открывают доступ по группам.
4. Проектный файл может попасть в репозиторий и к коллегам, а Kilo Code намеренно не подставляет `{env:...}` в проектном конфиге, чтобы чужой репозиторий не мог отправить ваш токен на свой адрес.
5. «Исполнитель и проверяющий» (evaluator-optimizer). Он полезен, когда есть понятные критерии качества.
